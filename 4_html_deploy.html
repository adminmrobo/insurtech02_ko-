결론부터Conclusion first

과제가 요구하는 대로 결론을 맨 앞에.

결론: 그대로는 적용할 수 없다

  1. 모델 ≠ 계수. 문항 2의 모델은 sklearn 객체(Pipeline: 표준화 → 로지스틱)이고, 브라우저는 파이썬 객체(pkl)를 읽지 못합니다. 계수만 옮기면 표준화·인코딩·정리 규칙이 빠집니다.
  2. 학습 입력 ≠ 배포 입력. 학습 데이터는 정리(118세 → 36세, 상위 10개국 + OTHER, 성별 빈칸 → Unknown)를 거쳤지만, 현장 입력은 원본 그대로 들어옵니다. 규칙 하나만 빠져도 판정이 크게 달라집니다(아래 실험: 성별 규칙 누락 시 6,607명, 52.2% 변경).
  3. 문항 2의 모델은 평가용. 5-Fold 의 모델 다섯 개는 점수를 재기 위한 것입니다. 배포용은 학습 데이터 전체로 다시 학습하고, 임계값을 학습 데이터 교차검증으로 정한(0.4049) 하나의 모델이어야 합니다.

그래서 “모델 + 전처리 규칙 + 인코딩 사전 + 임계값”을 함께 내보내고, 브라우저 계산이 sklearn 과 한 명도 다르지 않은지 검증해야 합니다.

추론 (inference)
학습이 끝난 모델로 판정하기. 배포 환경에서 새 입력에 확률·판정을 내는 일.
인코딩 사전
범주 → 열 번호표. 각 범주 값이 어느 원-핫 열에 해당하는지의 목록.
기준 범주
drop_first 로 빠진 첫 값. 모든 원-핫 열이 0이면 이 범주로 계산된다.
분포 차이 (shift)
연습장과 시험장이 다름. 학습 때와 배포 때 입력·청구 비율이 달라지는 것.
기여도
점수표의 항목별 점수. 계수 × 표준화된 값. 판정 근거로 보여 줄 수 있다.
Pyodide · ONNX

글 · 안상선 ((주)M-Robo 대표)

설명용 모형인 것: 이 시리즈는 공개 학습용 여행자보험 데이터(63,326건, 원 출처 fintech-data/Revolution 의 travel insurance.csv 를 이 저장소 data/travel_insurance.csv 로 복사)를 그대로 씁니다. 가상 데이터를 만들거나 데이터를 증강하지 않습니다. 브라우저 실습은 교육용 구현이라 정식 코드와 숫자가 조금 다를 수 있으며, 다른 경우 그 자리에 밝힙니다. 판정 계산은 data/logistic_model.json 과 같은 값으로 이 페이지의 JavaScript 가 합니다. 시험 데이터는 원본 입력 그대로(정리 전)입니다.

주의: 교육용 예시이며 보험 가입·보험료·보상에 대한 조언이 아닙니다. 실제 보험 심사와 보험료 산정은 감독 규정과 계리 기준을 따릅니다. 특정 집단에 불리한 특성(예: 성별·나이)의 사용은 금지되거나 제한될 수 있습니다.
